# 聊天过程展示：架构评估与实现

日期：2026-09-12。后续公开思考与流式正文改进见[回复展示改进](reply-display-alignment.md)，下文的“仅状态”描述记录首轮交付；默认配置仍保持此行为。

用户要求先判断当前架构能否承载 WorkBuddy 式的过程展示，能支持就直接实现。本次结论是 **支持，不需要重构执行引擎**。主要缺口在聊天接口的公开数据投影和界面组件。

## 为什么现有架构支持

| 层          | 已有基础                                                                        | 原来的缺口                             | 本次处理                                                 |
| ----------- | ------------------------------------------------------------------------------- | -------------------------------------- | -------------------------------------------------------- |
| Engine      | Session / Run / Step / Attempt / Operation 独立标识；事件与状态一起持久化       | 部分模型活动、Skill 开始阶段没有落事件 | 补发已有 model.streaming、skill.selected 事件            |
| 事件与存储  | sequence、timestamp、分页回读、固定 highWaterMark、游标过期快照、源数据重新授权 | 原始事件不能直接送给浏览器             | 白名单过程投影；保留关联和顺序，排除私有载荷             |
| chat-server | 宿主身份隔离、授权读取、会话快照                                                | 只返回正文、草稿、工具最终状态与统计   | 返回可选 process 字段及受控的查询/结果摘要               |
| chat-core   | 串行刷新、活动期约 450ms 轮询、重连与取消                                       | 无过程 DTO                             | 新增 ChatProcessEntry；继续使用现有传输，不另建 SSE 链路 |
| chat-ui     | 原子组件、业务组件、页面和 Controller 分层                                      | 消息区缺少阶段列表                     | 新增 createRunProcess；页面和浮窗共享                    |

所以这次是沿着已有事件链补齐展示，不需要新建调度器、重放系统或监控产品，也不改变模型重试、冻结请求、未知写入结果的核验与预算规则。

参考依据：已完整阅读技术设计、运行时使用方式与实施计划；只读检查 WorkBuddy 重建仓库中 assistant-message-grouping 与 conversation-search 的展示职责，以及用户提供的截图。参考结论属于代码与截图确认，**没有实时操作 WorkBuddy 验证功能**，没有复制其模块、提示词、素材、私有地址或真实会话。

## 用户现在能看到什么

- 排队、请求模型、模型实际报告的思考状态、准备调用工具和生成文字。
- Skill 加载/失败/退出、知识检索、记忆读写、工具执行与结果核验状态。
- 已提交的公开阶段说明、模型重试/切换、恢复执行、上下文整理、输出修正、预算提示。
- 等待输入/确认的问题，取消、失败，以及每一步已结束时的耗时。
- 本轮累计活动耗时、已知 Token；有费率和账本数据时展示分币种费用估算，缺失或不完整时明确标注。

执行时正文与过程按顺序排列，连续过程在后继正文出现后局部收起；完成后保留最长正文与最后结论，其余按边界折叠，完成入口位于首个常显正文之前。最新规则见[回复元素行为](reply-presentation-behaviors.md)。用户主动查看详情时保持展开，可以随时再次展开已完成过程。工具的输入与结果分别可读，默认摘要来自宿主显式允许的字段。未变化的行和正文不重建，轮询不会反复打断展开状态或代码复制按钮的焦点。

## API 与兼容性

| 公开接口                          | 变化                                         | 迁移                                                                          |
| --------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------- |
| ModelStreamEvent.activity         | 可选 kind: thinking / tool-call；无正文      | 原 activity 仍有效，显示通用处理中；自定义适配器可逐步补充                    |
| model.streaming                   | 每次 Attempt 每种观察到的 phase 最多记录一次 | 使用现有事件类型；data.phase 为 thinking / tool-call / text / working         |
| skill.selected                    | 已授权并即将加载时记录                       | skill.loaded / skill.failed 继续表示结果                                      |
| engine.inspectSession             | 增加 observedAt，由 Engine 时钟生成          | 纯新增字段                                                                    |
| ChatRun                           | 可选 process；usage 可选 costs               | protocolVersion 仍为 1，旧客户端忽略新增字段，旧宿主没有 process 时保留原界面 |
| ChatAssistantDefinition           | 可选 describeProcess({name,input,output})    | 默认不返回原始工具参数与结果；宿主主动返回安全字符串摘要                      |
| @agent-runtime/chat-ui/components | 新增 createRunProcess()                      | 接收 ChatRun 的 update 与 destroy，可独立组合；整页/浮窗自动集成              |

describeProcess 在服务器上执行，仅用于显示；不能修改执行输入或结果。文档站只对六个只读资料工具开放查询词、文档标题/路径和短结果摘要。回调抛错不会影响聊天。工具关联使用当前 Step 和 Operation，避免供应商在不同轮次复用 callId 时串到旧查询。

## 可靠性和边界

1. **只显示有证据的活动。** thinkingDisplayRetention 为 none 时仍可记录“思考”状态，思考正文、原生协议块、凭据和提示词不会进入过程 DTO。模型不报告思考信号就不显示该阶段。未配置或未调用 Skill / Memory 时不会补出相应步骤。
2. **过程与答案分开。** 只保留提交成功的公开阶段文字，失败/丢弃尝试的草稿不进入历史；最终回答由原来的已提交结果显示。
3. **有界历史。** 每个 handler 最多缓存 32 个 Session；单 Session 最近 1200 条过滤后事实且序列化字符不超过 512000；一次最多补读 6000 条原始事件，按每页 1000 条和固定水位分页。每轮最多返回 600 条过程；缺少起点或超出回读范围时提示记录不完整。正文与最终结果继续来自 Run。
4. **缓存不替代授权。** 每次读取仍校验身份、保留期和数据来源；缓存只保存白名单字段。游标过期退回快照可用事件，不假造旧历史。服务器重启后可重新从保存事件回读。
5. **时间和费用有明确语义。** “已处理”使用 Engine activeMs，等待用户时不累计；前端只做最多 3 秒的短暂插值，停止更新不会无限走表。费用是配置费率下的估算，既不是供应商账单，也不是 WorkBuddy 积分。
6. **当前传输是快照轮询。** 过程约随活动期轮询更新，尚未改为 SSE。快照读取跨数次授权调用，状态快速变化时可能在下一次轮询补齐最后事件；不会承诺每一帧为数据库原子截面。
7. **交互能力没有被扩大。** 等待输入/审批及结果未知会显示当前状态；实际回答、审批、核验仍由已授权宿主调用 Engine 接口，通用聊天页没有新增审批表单。文档助手仍是六项只读工具，未开启跨会话记忆、业务写入或动态安装插件。
