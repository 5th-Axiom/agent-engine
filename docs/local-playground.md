# 测试页面操作手册

[返回文档导航](README.md) · [首次安装与启动](getting-started.md) · [遇到问题](troubleshooting.md)

这里介绍怎样通过网页测试模型。环境和模型已配置好后，在项目目录运行 `pnpm playground`，保持终端开启。

| 页面       | 地址                                       | 用途                                   |
| ---------- | ------------------------------------------ | -------------------------------------- |
| 本地测试   | [打开测试页](http://127.0.0.1:4318)        | 选模型、提问、继续对话、停止生成       |
| Debug 调试 | [打开 Debug](http://127.0.0.1:4318/debug/) | 只读查看配置、执行步骤、工具记录和错误 |

页面显示「本地已连接」后再开始。模型密钥已由服务端读取，网页不需要填写 Token。

## 认识页面的三个区域

| 区域               | 你可以做什么                                               |
| ------------------ | ---------------------------------------------------------- |
| 左侧「会话与设置」 | 新建对话、选择模型与场景、打开最近对话                     |
| 中间「对话测试」   | 输入消息、阅读回答、继续提问、停止生成                     |
| 右侧「本次执行」   | 看最后一次运行的状态、模型请求数、步骤数、Token 和工具调用 |

窄窗口下，先展开「会话与设置」来选择模型，执行详情会排列在对话下方。

## 测试一：普通问答

1. 点击「新对话」。
2. 选择模型。当前电脑配置了 `deepseek-chat` 和 `deepseek-thinking`；第一次可选 `deepseek-chat`。模型列表来自本地文件，新电脑只会出现自己配置的名称。
3. 将「测试场景」设为「自由对话」。
4. 输入「请用三句话解释 Agent 的工作流程」。
5. 点击「发送消息」，等待右侧状态变为「已完成」。

成功标志：中间出现回答，右侧出现执行记录。回答内容由真实模型生成，每次措辞可以不同。

输入框最多 8000 个字符。**Ctrl / ⌘ + Enter 发送，Enter 换行。** 欢迎区的「试试普通问答」也可以帮助填写示例问题。

## 测试二：让模型调用工具

1. 新建对话，选择「工具调用」。
2. 发送「请调用工具查询 DEMO-1 的库存，并告诉我还有多少件」。
3. 等待运行完成，查看右侧「工具调用」。

成功标志：出现 `demo.inventory` 调用记录，状态为「已完成 · 结果校验通过」，回答说明库存为 **24 件**。也可以查询 `DEMO-2`，演示值为 **7 件**。

这是只读的合成库存，不连接真实业务系统。以工具记录判断是否真的调用；仅有一句“24 件”不够证明调用成功。如果没有记录，确认场景选对，并明确要求使用工具。

工具场景通常需要先请求模型决定调用，再把工具结果交给模型整理，所以「模型请求」可能大于 1。

## 测试三：继续对话、刷新和恢复

完成库存查询后，在同一会话发送「把刚才查询到的库存加一，只告诉我结果」。预期回答为 **25**。这一步用于观察模型能否使用当前会话的历史。

然后刷新浏览器。当前会话及已保存回答应该仍能打开；也可以从左侧「最近对话」重新选择。

想测试服务重启后的续聊，可以在一次回答完成后，回到终端按 Ctrl + C，再运行 `pnpm playground`。刷新页面、打开原对话，发送下一条消息。保持原数据库与 `PROTOCOL_KEY` 不变，才能读取原有的受保护续接记录。

页面显示最近 50 个会话，以及当前会话最近 50 次运行；更早的保留记录可在 Debug 查看元数据。历史受保留规则约束，过期正文不能通过刷新恢复。

## 测试四：停止生成和切换模型

生成过程中点击「停止生成」，等状态从生成中变成「已停止」，再进行下一步。模型回答太快时，可能来不及点击，可以改用稍长的问题测试。

中途出现的文字是草稿；停止或失败后，不把草稿当作完整答案保留。已经发生的模型请求仍可能产生用量。

已有会话会固定模型和场景。要改用 `deepseek-thinking`，先点击「新对话」，再选择模型。Thinking 模式可以用于测试思考模型的回答和续聊，思考正文与原生签名不会显示在页面上。

新建对话、切换历史、关闭网页都不会自动取消其他正在运行的任务。要停止它，回到对应会话点击「停止生成」。

## 怎样读懂状态和用量

| 状态            | 意思                 | 你要做什么                                              |
| --------------- | -------------------- | ------------------------------------------------------- |
| 尚未开始        | 还没有发送消息       | 输入问题并发送                                          |
| 排队中 / 生成中 | 引擎正在处理         | 等待，或停止生成                                        |
| 恢复中          | 服务正在恢复已有任务 | 等待状态更新                                            |
| 已完成          | 本次回答已经提交     | 阅读结果，或继续提问                                    |
| 已停止          | 引擎已确认取消       | 可以发送下一条消息                                      |
| 执行失败        | 本次未正常完成       | 看错误代码，打开 Debug 或[排查手册](troubleshooting.md) |

「等待输入」「等待核验」是 SDK 支持的暂停状态。当前网页的两个场景没有提供审批或人工核验操作表单；接入这些能力时需要宿主程序处理，参见 [SDK 使用约定](sdk-usage.md)。

| 数字       | 怎样理解                                                   |
| ---------- | ---------------------------------------------------------- |
| 模型请求   | 本次运行尝试向模型发起请求的次数                           |
| 执行步骤   | 本次运行记录下来的步骤数                                   |
| 输入 Token | 供应商报告的输入用量，可能包含历史、指令及工具信息         |
| 输出 Token | 供应商报告的生成用量；供应商报告的思考用量属于输出的一部分 |
| 合计       | 供应商报告或可确定的总用量                                 |
| `—`        | 数据未知或尚未取得，不能当作零                             |

右侧统计对应**最后一次运行**。运行完成后用量还可能更新。没有配置费率时，不显示费用估算；即使有估算，也应以供应商账单核对实际费用。

## 怎样使用 Debug

在对话上方点击「查看本次 Debug」，可以直接打开当前会话。顶部「Debug 调试」则从会话列表开始。

Debug 目前部分栏目使用英文，可以按下面的顺序阅读：

| 栏目或字段             | 中文含义             | 主要看什么                                     |
| ---------------------- | -------------------- | ---------------------------------------------- |
| Sessions / Session     | 会话列表 / 当前会话  | 是否进入了目标对话，记录对应 ID                |
| Configuration versions | 配置版本             | 运行实际引用了哪个配置版本；展开查看保留的配置 |
| Runs                   | 每次提问对应的运行   | 运行状态、错误代码、配置版本链接               |
| Steps and attempts     | 步骤和模型请求尝试   | 用了哪个模型、请求次数、是否已提交             |
| Usage                  | 用量                 | Token 是否完整，费用估算是否完整               |
| Operations             | 工具等能力的操作记录 | 名称、所属 Run、执行状态和输出校验状态         |

例如库存工具正常调用时，Operations 中会出现 `demo.inventory`；`executionStatus` 为 `succeeded` 表示执行成功，`validationStatus` 为 `valid` 表示结果符合声明的格式。

排查一次失败，先找到对应 Run 的错误代码，再看 Steps 和 Operations。Debug 只读，不提供发送消息、改配置或重新执行按钮；查看执行中的最新状态需要刷新页面。点「返回本地测试」可回到测试页面。

输入、回答正文、工具原始回执、模型密钥和私有思考内容在 Debug 中隐藏。查看聊天正文请回测试页。本地启动器自动处理 Debug 所需的内部认证，不需要手动输入模型 Key。

## 数据和页面范围

模型配置在 `.local/models.json`，凭据在 `.secrets/credentials.json`；修改后重启服务，详见[配置教程](local-model-configuration.md)。聊天记录保存在数据库，浏览器只保存当前会话标识和本地连接 Cookie。

| 可选环境变量                    | 作用                                                                  |
| ------------------------------- | --------------------------------------------------------------------- |
| `AGENT_PLAYGROUND_PORT`         | 更改 4318 页面端口，例如 `AGENT_PLAYGROUND_PORT=4319 pnpm playground` |
| `AGENT_PLAYGROUND_DATABASE_URL` | 使用另一份专用开发库；指定后脚本不会替你创建数据库                    |

默认数据库是容器里的 `agent_engine_playground`。不要把自定义地址指向生产库或另一运行中 Engine 的数据库。

页面约每 450ms 读取生成中的文本快照，空闲时低频刷新；文本逐步出现，但不是直接转发原始流。回答以纯文本显示，不渲染模型输出的 HTML。

页面适用于信任当前电脑使用者的本地开发，固定监听 `127.0.0.1`。任意模型地址、业务工具管理、审批工作台、文件上传、知识库管理及远程部署界面不在当前页面范围。

## 做完这些，就完成一次手动检查

- [ ] 普通问答完成，并看到执行记录。
- [ ] 库存查询出现真实的 `demo.inventory` 工具记录及预期结果。
- [ ] 同一会话可以继续提问，刷新后能找回记录。
- [ ] 生成中可以停止，并看到「已停止」。
- [ ] 可以进入当前会话 Debug，并返回测试页。
- [ ] 能区分 Token 未知、Token 完整和费用估算。

自动页面检查使用 `pnpm verify:playground`；它使用预设模型，完成后关闭临时页面。实际浏览器、真实模型和数据库重启的历史验证结果见[验收报告](release-acceptance.md)。
