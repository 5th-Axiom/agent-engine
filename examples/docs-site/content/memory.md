## 读取另一个会话的聊天内容

如果想查“另一个对话中说过什么”，无需先保存成长期记忆。本站标准助手已接入 `sessions.search`（搜索历史会话）和 `sessions.read`（读取会话内容），可以直接问“查一下另一个会话中青柠项目约定用哪个端口”。处理过程会显示真实查询与读取记录。

开关位于聊天右上角 `···` →「配置」→「工具」。新会话默认启用；旧会话保存过配置时，逐项开启这两个工具并保存。它们与「知识与记忆」中的偏好读写开关分开。

仅能读取当前浏览器身份自己的文档对话，按关键词搜索并分页返回用户消息和助手回答。图片只显示数量，不含系统提示或工具原始载荷；正在回复的轮次需写入历史后才可读。归档会话可读，已删除、到期或失权的来源不可读；依赖失效来源的派生会话也会拒绝读取和续聊。更换浏览器或丢失身份 Cookie 后，不能访问原身份的历史。搜索没有接入语义索引，未读完时助手应说明范围。

## 约定与排错

### 从 IM 控制读取和保存

在 IM 顶部点击「配置」→「知识与记忆」，可以分别控制每个已接入存储的「读取历史记忆」和「保存新的记忆」。点击保存后对本会话后续发言生效。

如果开关置灰并显示「未接入记忆存储」，先按本文代码在后端配置 `memory.stores`。本站标准启动器已经接入 PostgreSQL 长期记忆；自定义宿主若出现该空状态，需要补齐后端适配器。普通会话历史会用于同一会话的续聊，与跨会话存储分开管理。

SDK 的 `read.strategy: "none"` 只停用自动读取，仍允许模型按需显式读取；完整关闭需设 `read.enabled: false`。该字段省略时默认允许读取。例如在已有存储配置上：

```ts
store.read = { ...store.read, enabled: false };
// store 是 config.memory.stores 中的现有存储；随后按版本比较更新 Session 配置。
```

关闭读取不删除长期记忆，也不抹去已经进入对话的信息；需要全新上下文请新建会话。写入有独立开关，且继续遵循宿主的身份、业务幂等、审批和版本检查。

当前会话历史无需 Memory。自动记忆每个 Run 读取一次，并在重试中冻结；显式读取有独立执行记录。namespace 必须来自可信身份，与模型参数分开。上方最小示例只读；本站的完整写入适配器还实现了业务幂等、审批和版本比较。

模型不调用能力时，先检查 Session 声明和模型的 tools 能力，再检查事件与 [Debug](/docs/debug/)。权限错误需核对实际主体与宿主策略。接口细节见 [API 参考](/docs/api/)。


## 在文档助手中实际体验

1. 在对话中说“请记住：我的项目用 TypeScript，回答请带验证步骤”。助手提出写入后，会先展示记忆内容；点击「允许这一次」才会保存。模型未提出写入不代表已保存，以执行记录和记忆列表为准。
2. 新建对话，询问已有偏好。每轮自动读取当前身份最近更新的最多 5 条记忆；这个示例适配器使用近期记录，没有接入向量检索服务。
3. 打开[长期记忆](/ai/capabilities/#memory)查看内容、版本与到期时间，也可以删除。匿名身份由签名 Cookie 识别，不会关联另一个浏览器或设备。

默认保存 30 天，AES-GCM 加密存储，身份由服务端传入。到期即停止读取，启动时和每分钟清除过期密文；删除清除内容，保留无内容版本标记与幂等回执，避免旧页面误删后来重建的记录。`redactPII` 示例过滤邮箱和手机号等简单模式，不是完整的敏感信息识别服务。

关闭「保存新的记忆」后不再向模型开放写入能力；读取可单独保持开启。关闭读取不会删除数据库记录，也不会抹去已经进入当前聊天的信息。已有会话曾保存过配置时，新加入的能力默认关闭；需要启用可点击「恢复助手默认」再保存。

完整宿主实现在 `examples/docs-site/capabilities.ts`。数据库和协议密钥必须稳定，换用密钥前需迁移已加密内容；丢失 Cookie 后无法以原匿名身份读取记忆。
