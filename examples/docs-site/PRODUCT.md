# Agent Engine 官方文档站

## 用户与任务

面向第一次将 Agent Engine 接入自己产品的中文开发者。传统模式按环境、会话、图片、工具、Skill、知识、记忆、事件和 Debug 等用户任务编排。提供创建对话、嵌入界面、完整示例三个入口，每条说明前置、代码位置、执行、结果和排错；可导出到独立项目验证。本地源码演示作为附录。

## 已确认

- 用户要求可操作的文档站，直接实现后看实际页面调整（code-led）。
- 默认进入 AI 模式，使用自己的前端 SDK 页面式对话框并接入检索工具；顶部可切换传统文档站模式，文章内保留 icon 助手。允许普通聊天，项目事实依据资料回答。
- 聊天内容左侧展示对话列表；界面提供“当前会话”和“工具”的查看入口，传统模式悬浮助手与 AI 页面共同使用通用 SDK 实现。
- 内容要适合初次接入者，兼顾电脑与手机，说明代码放在哪里、哪些是 SDK API、哪些业务函数由接入方实现，以及验证结果。
- 用户明确修正方向：重点为“用户如何接入、如何使用”，前端 SDK 与后端 SDK 分别讲解，不能把本机运行教程当成主线。
- 传统模式第一篇提供用途与三个等价接入入口。产品交付可能是 npm、CLI、压缩包或安装包，尚未确定；当前源码与本地 SDK 可用，未交付入口不展示下载动作。
- 用户把场景文档作为 API 易用性的验收：允许简化公开接口，需保留可靠性、授权与可恢复约定，并写迁移总结。
- 支持图文、多图、粘贴/拖拽/预览/重试和历史工具图片；助手消息支持安全 Markdown 与代码复制。历史和普通事件仅保留附件引用，实际图片内容单独鉴权。

## 实现范围与事实

独立本地文档宿主，复用本仓库 Engine、chat-ui、chat-server。标准启动器声明八个只读工具：六个 binding 覆盖文档搜索／读取、公开 API 声明、示例查找、公开源码搜索／读取；docs.httpCatalog 通过实际本地 HTTP 服务读取目录，docs.mcpSearch 通过实际 Streamable HTTP MCP 服务检索手册。源码为启动时 Git HEAD 的固定白名单快照，不含未提交改动。凭据继续由已有本地加载器在服务端读取。标准启动器使用独立 PostgreSQL 数据库，不占用 Playground 的管理锁。当前追加范围不部署、不发布。

产品能力以当前可执行使用文档和导出接口为准。M0–M3 已实现；分布式调度、真实 replay 和监控产品不是首版能力。包尚未发布到公共 npm。

## 设计判断（本任务推定）

AI 对话为默认入口，传统阅读为可切换入口。读者通常在桌面终端与浏览器之间对照操作，默认明亮中性背景，提供深色模式。继承 chat-ui 的白底、深蓝文字、蓝色交互、系统字体与平直分隔线。传统模式以三个完整接入入口和场景目录组织手册。

AI 模式使用 mountChatPage；传统模式的总览提供创建对话、嵌入界面与完整示例入口。“询问本文”保留文章位置，打开 mountChatWidget 并填入可编辑问题，由用户发送。模式切换共享会话与同一标签页文字草稿；来源链接提供文档或带行号的源码。未发送图片草稿不跨页面保存。

## 交付与验证

搜索、文章导航、复制代码、目录锚点、主题、移动导航、真实聊天与错误恢复均可操作；验证匿名会话隔离、八个只读工具、路由边界、模式切换、浏览器交互和真实模型，各轮范围以验收记录为准。截图及私有运行记录放入忽略目录。本次按 Impeccable 技能显式要求进行独立设计终审与系统记录，结论见验收记录。

文档助手沿用通用 SDK 的有序处理过程：真实模型阶段、已开放资料工具及知识／记忆操作的查询词和结果摘要、耗时与已知用量。执行中展开、完成后可收起；传统模式浮窗与 AI 页面共享实现。Skill、知识与记忆只有在宿主配置并实际执行时才展示；本站已接入两项 Skill、正式知识库、长期偏好记忆及问题／表单／审批，未提供插件安装。

输入编辑工具栏与共享 Chat UI 同步：本站采用 Enter 发送、Shift+Enter 换行，可通过输入设置切换；长输入自动增高、可展开，中文输入法确认不误发，空输入 ↑ 找回上一条文字。本站读取已配置的本地模型 Profile 并提供下一轮模型选择，思考和图片标记来自真实配置；空闲历史会话沿用授权/CAS 更新助手配置。本站显示“自动技能”、integration-guide 接入指南与 troubleshoot 问题排查；未声明 Skill 的其他宿主仍隐藏选择器。尚无 ASR，麦克风置灰并解释原因；不申请录音权限。维持白色开发工具界面，窄屏选择器允许换行以完整显示正常名称。

能力工作台追加：`/ai/capabilities/` 使用四个原生锚点入口：已接入能力（overview）、长期记忆（memory）、配置实验（experiments）与会话调试（debug）。延续现有白色／蓝灰工作台与蓝色操作，按 code-led 方式扩展，没有新批准视觉稿或设计方向。能力目录来自实际宿主配置；设置页提供记忆管理和实验入口。

标准助手配置 inline `integration-guide`、版本与 hash 固定的 loader `troubleshoot`、正式 KnowledgeBase `manual`，以及按浏览器身份隔离的 `preferences`。偏好加密持久保存，模型提出写入后由原生审批区显示内容，用户允许一次或拒绝；更新使用版本 CAS，删除保留无内容版本 tombstone，默认 30 天到期并清理加密正文。关闭读取、删除记忆和删除会话各有独立范围，已有历史内容不会随之消失。问题与接入表单通过共享 Chat UI 原生控件提交并继续同一 Run。

十三项配置实验以合成模型和数据执行真实 SDK，每次使用独立 MemoryStore，不调用外部供应商，也不改写访客真实会话或记忆；报告保存在宿主 Store。覆盖输出／引用修复、重试／备用模型、参数修复、写结果核验、预算、上下文整理、配置冻结、事件与生命周期。会话调试读取当前身份的文档会话快照，提供归档、取消归档与确认删除；活动 Run 阻止生命周期变更。401 清除身份内容、禁用控件并提供重新连接，迟到响应失效；403 清除被拒记录并在适用时刷新仍获授权的列表。取消删除、删除与归档后恢复键盘焦点。

能力扩展交接证据为 38 文件／192 项通过（含独立真实 PostgreSQL 与崩溃测试；全量源码检查显式排除并行任务的 .local 验证副本）、十二张确定性浏览器截图、六次合成对话请求且无浏览器错误。另有已授权真实供应商四个 Run，验证获准记忆写入后新 Session 回读、两项 Skill、KnowledgeBase、HTTP 与 MCP，标准启动器重启后的 PostgreSQL 记忆回读也已通过。互动实验不代表完整供应商或崩溃验证；截图中的合成 MemoryStore 宿主不改变标准 PostgreSQL 启动器的事实。最终终审和验证范围见 [ACCEPTANCE.md](ACCEPTANCE.md)。ASR、CLI 分发、分布式调度、真实 replay 与监控产品仍未交付。


回复展示补充：模型与宿主显式许可、保留策略允许时，展示供应商实际返回的公开思考内容，摘要与正文语义分开。默认关闭，签名与遮蔽块不进浏览器。文档站本地配置已显式开启；旧未保留内容不能补回。保留原生工作界面，当前阶段、思考与工具更突出，已结束基础状态收进执行详情。Markdown 保留节点，接收到的文字短时逐帧呈现；历史立即显示、重试草稿立即撤回，减少动态效果及后台页面停用缓冲。用真实事件与供应商返回值展示过程，不补造未发生的思考或动作。


会话配置追加：IM 顶部“配置”在新标签页打开当前会话的网页；首条消息前打开只创建空会话、保留草稿。四类为工具、Skill、知识与记忆、回答与上下文，支持搜索、逐项开关、明确保存及恢复助手默认。只收窄宿主已接入能力，保存用于后续 Run，活动 Run 保持冻结；记忆读写独立，关闭读取不清空当前聊天记录。未接入能力提供禁用/空状态及文档。版本冲突与网络错误保留草稿；明确失权清掉旧目录并禁用操作，成功重读后恢复。桌面左侧分类，手机两列分类加独立滚动内容区和底部操作；延续既有明暗主题、系统字体与原生控件。
