## 真实验证

本机默认真实 Provider + 独立 PostgreSQL 数据库已通过三轮连续问答：密钥配置问题实际执行 docs.search；普通聊天未调用检索；分布式调度与公共 npm 发布状态的回答符合当前项目资料。页面刷新后，三轮历史仍可恢复。默认回答使用适合当前 IM 的纯文本。

初次真实测试暴露连续检索片段过长导致 CONTEXT_BUDGET_EXCEEDED，已将每次最多三篇片段限制为 1600 / 900 / 900 UTF-8 字节，并启用既有历史工具结果裁剪和有界压缩配置。修正后的连续问答通过；新增字节上限及 Unicode 截断断言。没有提高模型上下文窗口来掩盖问题。

复现命令：`pnpm smoke:docs`，详细输出仅保存在被忽略的 `.impeccable/review/provider-smoke.json`。这不代表所有供应商、长会话或真实手机系统已经验证。

## 设计验证

代码优先实现，继承现有工作台主题。桌面、手机、深色、入门文章与手机 IM 五份截图已查看；检测器返回 `[]`。首轮发现移动端悬浮提示文案遮挡正文，已移除手机上的提示文案，保留带可访问名称的图标。

本侧对话禁止子代理，终审和设计记录采用 Impeccable 的本线程降级流程，不冒充独立代理评审。第二轮五视图截图与最终真实问答截图已检查；结论为 ship，范围为这些视图与已执行的交互。移动端提示遮挡及默认回复 Markdown 装饰问题已解决；设计系统已记录在 DESIGN.md 和 .impeccable/design.json。

`pnpm typecheck`、六包构建、文档浏览器/HTTP 验证、真实 Provider smoke 和冻结锁文件检查通过；Git 可纳入的 161 个文件与本地真实凭据匹配数为 0。测试未运行生产外部动作，没有部署、提交或推送代码。

## 限制

- 本地启动器没有公网发布，生产身份、持久限流、日级额度及运维仍由正式宿主负责。
- 文档检索按关键词和中文双字片段排序，无外部向量数据库；引用来自可见资料，但不自动证明答案语义正确。
- 当前 IM SDK 按纯文本显示回答；有效来源链接在文档页面末尾提供。
- 手工入门文章与源码能力变更需要维护；三份详细教程在每次启动时直接读取源码手册。
- 没有改动 SDK 核心，未重跑与本站无关的全量 PostgreSQL 崩溃矩阵；本站新增行为单独验证。
